# 使用指南

[项目首页](../README.md) · [维护与发布](RELEASING.md)

## 安装和启动

在[客户端 Releases](https://github.com/qmx-acm-data/qmx-acm-notebook/releases)下载对应版本的 `QMX-Notebook-Setup-<version>.exe`，运行后按提示安装。安装无需管理员权限，会创建桌面和开始菜单快捷方式，卸载保留个人数据。浏览器下载本身不会创建快捷方式。

便携版需解压整个目录，运行「启动.cmd」，不能只复制 exe。普通启动失败时可试「兼容启动.cmd」；兼容模式另加 `--no-sandbox`，会降低 Chromium 进程隔离能力。当前验证机器曾需要兼容模式。程序未签名，Windows 可能提示未知发布者，请核对来源。GitHub 的 Source code 压缩包是源码，不是安装包。

## 平台账号与主页概览

在设置的“竞赛平台账号”点击“绑定账号”，粘贴对应平台的 HTTPS 个人主页链接。验证成功后仅显示用户名，再次点击可更换或解除绑定。绑定与公开数据快照仅保存在本机，独立于 GitHub 登录，不需要平台密码或 Cookie。

主页采用紧凑布局，集中显示比赛提醒、待做题目、学习任务和“做题与比赛总览”，不再显示六项快捷入口。tricks、公共题库、算法笔记与个人收藏通过侧边栏访问。总览汇总总解题、总提交及最近比赛；右上角选择平台只切换每日解题、总解题、总提交和最近一场比赛，两张 Rating 图、账号列表和下方比赛历史保持汇总显示。刷新按钮按当前选择更新，展开统计可增大图表和记录区域。Codeforces 和 AtCoder 各有完整公开 Rating 历史折线图，悬停或聚焦圆点查看比赛信息。总解题为各平台题数相加，同题跨平台不去重；未知字段不视为零，合计附带数据覆盖率。洛谷按主页“提交”栏原值计入总提交，来源说明保留平台显示口径。

每日热度图按北京时间汇总各平台：CF、AtCoder、牛客在取得完整公开提交历史后，按每题首次 AC 日期去重；洛谷采用官方每日通过题数，覆盖最近180天截至昨日，数据非实时，不能保证与首次AC口径相同。选择最近一年或上一年，鼠标悬停、点击或键盘聚焦日期时弹出两行浮窗，显示日期与总通过数；覆盖不完整时标记“已知”。Rating 圆点、最近比赛和比赛记录也会弹出浮窗，第一行加粗比赛名，其后显示 Rating 变化（若公开），最后显示赛时通过题数/总题数（若可核实，例如3/7）；不使用补题通过数代替赛时通过。完整区间外显示未知。力扣若只能取得最近一段 AC 列表，不据此推算全年热图；公开通过数和提交数均为零时显示真实空日历。

重启先恢复本机缓存，刷新失败保留旧数据与时间。Codeforces 超过20,000条提交、AtCoder Problems超过20,000条或时间边界不完整、牛客超过20页时不以截断历史计算完整日历。AtCoder Problems为第三方来源，可能延迟；牛客只统计公开编程练习；洛谷只展示主页最近评定比赛；力扣国服与国际服分别读取公开资料，无公开竞赛积分不代表从未参赛。来源及限制可展开面板底部说明。

应用源码与安装包不包含默认个人绑定。全新用户的五个平台均显示“绑定账号”；验收时使用的个人链接和数据只保存在独立测试目录，不进入发布资源。

## 待做题目与学习任务

“待做题目”用于收集稍后练习的题目：粘贴题目链接，可同时粘贴名称，也可单独填写可选名称；未填写名称时按链接生成题号或路径名称。支持 Codeforces（含 contest/gym）、AtCoder、洛谷、牛客、力扣国服/国际服、Hydro 和 AcWing 的官方题目 HTTP/HTTPS 链接；不接受任意网页、含凭据或自定义端口的地址。同一链接已在未完成题单中时会提示重复，点击题目名称可打开原题。

“学习任务”填写标题即可添加，截止时间可选。点击截止时间按钮打开日历弹窗，可选择日期与时刻，也可使用今天、明天、+7天或清除；确定后应用，取消或按 Esc 放弃本次选择。截止时间按本机时区填写和显示，与比赛提醒统一使用北京时间的规则不同；有截止时间的未完成任务按时间先后排列，逾期会标记。

点击任务标题打开只读详情，查看完整标题、截止时间与任务说明；修改标题、截止时间或补充说明时点击该行“编辑”。补充说明最多 2000 字，任务标题和题目名称最多 180 字。题目与任务均可勾选完成、取消完成或确认删除；已完成内容在单独分组中保留。两类列表可独立收起并滚动查看，每类最多保存 500 项。

题单与任务保存在当前设备、当前系统用户数据目录的 `planner.json`，无需 GitHub 登录；切换 GitHub 账号或资料库仍使用同一份计划，不按 GitHub 账号隔离，也不上传或同步到 GitHub。重启恢复已保存内容，备份方法见[数据安全与备份](#数据安全与备份)。

## 每日一题

主页按筛选条件抽取一道题，而非所有用户共享的固定日历题。洛谷难度可以分别设置最低和最高等级，两端均包含；两端选同一等级为精确筛选，单侧留空为不限该端。最低高于最高时明确提示，并在获取题库数据前拒绝该范围。等级显示采用简短名称，例如“普及/提高−”显示为“普及”，旧索引中的官方名称仍按同档识别，原始记录不改写。先在符合条件的平台间等概率选择，再在该平台题目中随机选择；“换一道”排除当前题号和同链接副本，不会因缓存和远程来源 ID 不同再次抽到同题。已有的本地／当前仓库记录先按账号和资料来源限制。

离线题库索引按平台读取，已有分片不重复联网；仅缺失的平台补充公开来源。本地或公共题解范围不触发外部题库请求。CF、AtCoder、力扣、牛客和 LibreOJ 的完整成功结果在本进程复用 5 分钟，并合并同时发生的同来源请求；失败或不完整结果仍可重试。CF／AtCoder 刷新索引时复用同一轮探测下载的数据。现有按题量增量同步仍不保证覆盖老题元数据变更，必要时需完整重建索引。

## 题库缓存机（设置）

设置中的“题库缓存”按平台维护离线题库索引。首次需要完整建库：逐页抓取公开列表（洛谷、力扣、牛客、LibreOJ），CF 与 AtCoder 各一次请求取全量。每完成 20 页会写入一次检查点，因此长任务可以暂停、关闭后继续，失败也只丢当前批次，不会整轮作废；已抓到的题目先合并进分片。

平台列表总数与上次完整扫描的上游总数比较：总数不变时跳过分页抓取；CF／AtCoder 仍需读取整表才能知道是否增长。洛谷、力扣和 LibreOJ 从列表尾部重叠页检查新增题；牛客列表按新题在前排序，因此从首页检查，直到已找到足够覆盖总数增长的新题且遇到整页已知题。总数减少时保留本地题并提示完整重建；总数没变并不保证老题内容没有更新。力扣原始列表包含付费题，实际可收录免费题数量可以少于上游总数，增量判断使用上次上游总数，避免每次误抓尾页。完整重建先把旧分片备份为 `.bak`，再重新建库，需在设置二次确认；暂停或失败时分片可能暂时不完整，继续完成后才记录完整同步成功时间。

设置面板显示每个平台的状态、已抓取／总数、新增题数、更新时间和失败原因；运行中可暂停，再次点击“增量更新”从断点续传。任务状态保存在 `library/sync-state.json`，元数据写入 `library/meta.json` 并保留未知字段。抓取只使用各平台公开列表接口，页面之间默认间隔 250 毫秒；不要在短时间内反复触发完整重建。完整重建会显著增加题目数，抽题范围也会随索引扩大。

## CLIST 缓存共享

设置中的“CLIST 缓存共享”用于多人复用已查询的真实 CLIST 正分。点击“导出 CLIST 缓存”生成 `qmx-clist-rating-cache.json`；文件仅包含共享格式版本、导出时间，以及每题的官方链接、CLIST 分数、资源站点、查询时间。Key、用户名、个人题解、人工／AI 补充及查询失败历史均不会导出；零分不作为评分共享。客户端不会自动上传文件。

可以把导出文件放到你选择的公共 HTTPS 下载位置，其他用户通过“导入并合并缓存”或填写“共享缓存文件地址”后点击同步获取。无需 CLIST Key 即可导入／下载已有分数；没有配置公共来源时不假定有共享基线。来源地址成功同步后保存在本机，正常资料“同步”也会尝试更新该来源；同步失败继续保留本机评分，不影响资料同步。实际公开发布需由用户另行操作。

合并按标准题目链接与查询时间进行：新题加入，较新的传入评分更新，较旧或同一时间的冲突保留本机。不会用空值、零分或未收录结果清空有效评分，也不会删除个人独有条目。先完整校验文件大小、版本、可信题目链接、平台、数值和时间，再原子写入并保留上一份备份。原始 `clist-rating-cache.json` 也可导入，但原生／社区难度导出模板不属于 CLIST 数据，不再提供该功能。

共享缓存与本机主动查询写入同一评分缓存。已导入的有效正分直接用于抽题，无需逐题重复获取。需要更新时用分页批量刷新六个平台的最新评分，再导出贡献给维护者合并；旧版逐题队列会跳过已缓存的正分。题目旁“刷新评分”始终保留，允许用自己的 CLIST 配置强制更新当前题。原生或社区难度仍从正常题库索引读取，未受此次共享功能改动。

## 初始基线与 CLIST 分页批量缓存

应用内置 2026-11-22 实际导出的 37,200 条真实 CLIST 正分。正常首次启动会自动与本机缓存按时间合并，保留较新个人评分和独有条目，无需 Key 或逐题等待。相同内容哈希已应用且本地存在有效缓存时不重复写入；升级包有较新基线时重新合并。静态元数据记录数据来源和 SHA-256，不包含凭据。

设置中的“CLIST 批量缓存”按 CF → AT → 力扣 → 洛谷 → 牛客 → LibreOJ 顺序请求，每页最多 1,000 条正分，共用 CLIST 限流。每页成功后立即合并缓存并保存 offset、页数和最后一个 ID；暂停在当前页完成后生效，重启可续传。完整结束后再次点击刷新会从第一页重新更新。批量刷新需个人 Key，使用初始／共享缓存无需 Key；分数为空或 0 不会清空已有正分。题目旁单题“刷新评分”继续保留。

缓存记录数不等于本地题库实际匹配题数。CLIST 与原平台覆盖范围不同，牛客比赛链接不会按标题猜测并映射到 ACM 全局题号；只在题目身份相符时使用评分。原生／社区难度和已审核补充仍按原规则保留。

平台主行分别显示“待查 CLIST、已缓存、总题数”，满足“总题数＝待查 CLIST＋已缓存”。待查数包含尚未查询及查询后无有效正分的题，处于台账冷却期的题不会重复请求。次行的“仍无可用难度”沿用原生／社区缺口口径，另列“原生/社区缺失”和“已补”，满足“原生/社区缺失＝仍无可用难度＋已补”。取得有效 CLIST 正分或保存已审核人工／AI 难度后，待补数量会在轮询时减少；0 分、空评分、未收录和失败不减少。删除人工补充后，如果没有其他有效 CLIST 缓存，待补数量会增加。原生/社区缺失本身不会因参考补充而改变。

旧版客户端的逐题补全入口保留兼容（新版优先显示分页批量缓存，不再要求每人从头逐题查询）。旧入口每批最多查询 100 题，本批“已处理”与各平台“本批已查”口径一致，细分为“查到／未收录／无评分／请求失败”；“历史记录跳过”另列，表示已查过或仍在冷却期的题，不等于本批未找到。CLIST 已收录题目但评分为 0 或空时计“无评分”，不是链接匹配失败。每次点击开始（包括暂停后继续）启动新批次并重置本批计数，通过历史台账继续处理剩余题；重启后保留上一批结果，实际未运行的中断任务显示已暂停。

除 Codeforces 和洛谷外，CLIST 明确未收录且结果使用参考难度时，题目下方显示“参考难度与实际难度可能存在很大偏差”。批量台账中的明确未收录结果也会在后续抽题时带出提示；未查询、请求失败、无评分或旧记录原因不明时不冒充未收录。

查询记录保存到 `difficulty-backfill-ledger.json`：查到正分的永久跳过，未收录／无评分 30 天后重试，请求失败 1 天后重试，避免反复请求。新记录附带原因；旧记录没有保存具体原因时显示未分类提示，不推测来源。缓存只保存在本机，不上传资料库。

CLIST 评分单独保留，并可生成“CF 参考”和“洛谷参考”。当前规则版本 `clist-elo-reference-v2` 以 CLIST 分数取整到百位、保留低于 800 的参考值（例如 377→400）、上限 3500 作为 CF 数值参照，再使用项目洛谷分档；这是低置信、未跨平台校准的启发式，不是官方等价，也不会覆盖 CF 原生 Rating 或洛谷原生等级。原始分数及超出参考显示范围的说明保留。[CLIST 作者明确说明各站评分未标准化](https://github.com/aropan/clist/discussions/314#discussioncomment-8087059)，因此不能把该规则称作精确换算。逐题评分需在设置中配置合法 API Key；未配置、未找到或请求失败均明确提示。抽题本身只读取已缓存评分，不会联网查询，因此不会因限流变慢；配置后通过题目上的“刷新评分”或“难度补全”批量获取，六平台按题目路径匹配 CLIST 的 URL（CLIST 保存的链接可能带比赛参数或是 contest 路径），并校验返回题目身份。CLIST 分数为 0 时按“无评分数据”处理，不生成 CF 0 或洛谷入门参考，也不计为补全成功；历史零分缓存兼容读取为无数据标记，其他官方／社区／人工难度保持独立。成功的正分评分持久保存到用户数据目录的 `clist-rating-cache.json`，重启后继续复用，包含原始分数、来源与查询时间，不包含凭据；之后即使未配置 Key 也可读取已有缓存。结果中的“刷新评分”会跳过旧缓存重新查询，仍遵守 CLIST 限流；刷新失败或返回未知分数时保留上次成功值，标明使用缓存。首次没有分数的失败请求冷却 2 分钟，不把失败或空值写成有效评分；不是每题都保证有评分。已有其他来源的启发式估算继续明确标为参考。牛客竞赛题库的数值难度与专题的 1–5 档不同，索引保留原生数值而不当作 CF 评分；已生成的旧牛客分片需完整重建才能消除旧值。

洛谷原生难度独立于 CLIST 缓存，保存官方编号 0–8：0 暂无评定，1 入门，2 普及−，3 普及，4 普及+/提高−，5 提高，6 提高+/省选−，7 省选/NOI−，8 NOI/NOI+/CTS。有原生等级时不因 CLIST 未获取而显示待评级。旧索引缺少原始编号时，读取随应用附带的已核验官方题号／等级快照恢复，不通过旧标签猜测；新同步的有效原始编号优先于快照。资料库或本地题解的同题空难度不会遮住已缓存原生等级。刷新题库后也会更新当前抽题结果的元数据。

洛谷题库导入兼容 JSON 和页面内数据，只映射官方 `Algorithm` 类型（当前 type=2）的标签，排除地区、年份、赛事来源、特殊题目与 Others。内置算法目录当前是 22 类、262 项；旧仓库缓存不完整时也会与完整离线预设合并，同 ID 改名不重复新增。每日一题不提供已知非算法或“洛谷标签#编号”的历史占位标签；原题解的历史标签不删除，仍可在题解筛选中使用。

标签选择器会合并实际离线索引中各平台已获取的算法标签，去重后注明 CF／LG／LC 等来源，并显示题量、有标签题数、唯一标签数和更新时间。AtCoder 等来源未提供标签时明确标记，不补造；洛谷只使用 Algorithm 类型，LibreOJ 的系统／赛事元标签也排除。题目结果固定显示标题、平台、CF／洛谷难度（缺失为待评级）和原题链接，算法标签默认隐藏，点击“显示算法标签”展开，新抽题后再次隐藏。抽题耗时显示本次客户端等待时间，覆盖统计注明离线索引、在线或混合来源，不把离线毫秒数冒充冷网络取题时间。

选题请求中切换页面后，返回仍能接收结果并保留筛选；切换账号或资料库会清空每日一题界面上下文，旧请求和旧标签弹窗回调不能更新新账号的结果。

## 缺失信息补充与 AI 建议

每日一题结果提供“补充缺失信息 / AI 建议”。仅官方缺失的算法标签或难度允许填写；两个字段分别保护。例如官方有标签但没有难度时，只能补难度，官方两项都有时不能保存补充。AtCoder 社区难度、CLIST 分数和启发式参考不冒充官方难度。旧力扣索引缺少原生档位时保守锁定，刷新题库恢复官方档位后再判断。

人工补充需填写算法标签、CF／洛谷参考难度及依据。AI 使用自己配置的兼容 OpenAI 接口、模型和 Key；HTTPS 服务地址或明确的本机 HTTP 服务可用。Key 用系统 safeStorage 加密保存，不回显到界面。点击“生成”时只发送当前题目的标题、平台、原题链接和你确认粘贴的公开题面文本；不会自动发送个人题解、草稿或整个题库。使用实际服务可能产生费用，以所配服务为准。

AI 结果先进入“待审核”，不会参与抽题或标签目录。审核内容和理由后点击“采用建议”才生效，保留模型与 AI 来源；人工改写则按人工填写保存。补充保存后刷新当前题目，并用于后续抽题筛选和算法标签目录。官方数据后来补齐时自动优先官方值，补充记录保留用于回查；可以删除补充，原始题库不改变。

补充缓存单独保存在用户数据目录的 `problem-enrichments.json`，已采用结果与待审核建议都在其中；AI 配置单独加密保存在 `ai-auth.json`。这两份文件不上传资料库，补充信息按本机和标准原题链接共用，不跟随 GitHub 账号同步。备份补充缓存即可保留人工／AI 审核结果；损坏文件会明确报错并拒绝覆盖，请保留原文件后恢复备份。

## 搜索与筛选

公共题库采用紧凑横向列表，依次显示平台、题号、算法标签、题目、原生难度、作者和更新时间，不显示通过率。点击题目或在题目行按 Enter 直接打开完整题解，点击返回后恢复筛选、焦点和列表横纵滚动位置。公共列表不再设置选中预览区；窄屏可在列表内部横向滚动查看完整列。“本地题解”采用同样的紧凑列表和点击直达阅读，展示本机可见题解和当前 GitHub 账号在当前仓库上传的题解，并显示作者；计数与该范围一致。本人已上传题解按稳定的 GitHub 作者 ID 识别，账号改名不影响归属，未登录时仅显示本机未绑定记录，其他账号的私人记录不会混入。自建服务上的同号用户不视为当前 GitHub 用户。个人收藏已统一为紧凑收藏中心，具体用法见下文。

列表、卡片和题解详情可显示作者的 GitHub 头像，优先使用已有账号头像缓存；在线头像仅从 GitHub 官方头像域加载，失败或离线时保留首字头像。未绑定的旧本地题解显示“本地学习者”，不自动归给之后登录的账号。

搜索支持题号（如 `P1001`、`CF 1900 D`）、题目链接和多个关键词。空格分隔的词需要同时匹配，可跨标题、标签和正文命中；精确题号优先，其次按相关程度排序，无搜索时按更新时间排序。

平台、标签、作者展开后均可多选，并可在组内查找；同组条件任选其一，不同组同时满足。标签选择弹窗顶部持续显示“已选标签”，每项可点 × 移除，也可“清空已选”；搜索隐藏选项时仍能操作已选标签。勾选和移除均在点击“确定”后应用，取消不改变原选择；搜索与勾选保留选项节点和滚动位置。标签弹窗打开期间使用无背景模糊的遮罩，分类标题随内容滚动，避免标题累积遮挡选项；悬停和键盘焦点立即高亮。新题解初始无标签，上传或保存后再次新建不会沿用上一篇标签；继续编辑记录或恢复未完成草稿时保留该记录或草稿的标签。点击已选条件右侧的 × 可移除，点击“重置”清空搜索及全部条件。

难度面板一次选择 CF Rating、洛谷难度或其他原生难度体系，区间包含端点，切换体系会清除上一组条件，不做跨平台换算；其他平台的原生难度可多选。非洛谷平台也可独立保存补充洛谷难度，并参与洛谷难度筛选。启用难度条件后无对应难度的题目不会命中。最低值高于最高值会提示调整。颜色按 Codeforces 色阶、洛谷原生等级及 LeetCode 简单/中等/困难对应，深色主题使用适配的可读色值。

## 个人收藏

题解、Trick 和算法笔记阅读页均提供“收藏”按钮。个人收藏以紧凑列表统一展示类型、标题、作者、更新时间，可按“全部／题解／Trick／算法笔记”切换，并搜索标题、作者、标签或简介。列表不提前显示正文，点击后阅读，返回或 Esc 保留筛选与滚动位置；右侧星标可直接取消收藏。

新收藏仅保存在本机，按当前账号、资料来源与内容类型隔离，不上传到公共资料库。已有旧收藏标识继续兼容，不自动改写或删除。切换资料库只展示当前来源中可见的内容，本地题解按原账号可见性处理；他人的个人算法笔记不会进入收藏中心。远端内容删除或暂不可见时隐藏条目，保留收藏标识，避免同步失败清掉收藏。取消收藏不删除原内容，保存失败会恢复原收藏状态。题解的复习状态继续在阅读页维护。

## 明暗模式与配色

顶部的“明暗模式”只切换浅色和深色；“配色方案”独立提供瓷白、晴空蓝、雾紫、樱粉、暖杏、海盐青。每套配色都支持两种明暗，切换其中一项不会重置另一项，默认使用浅色＋瓷白。公共题库列表、本地题解与统一收藏列表的间距和字号在两种模式中一致。

设置中的外观选项可以即时预览；点击保存后保留，取消、关闭或按 Escape 会恢复打开前的外观。历史“灵感卡片”设置会迁移为浅色＋暖杏；已有独立配色时予以保留。主页、题库、算法、收藏、计划、比赛、账户、同步和编辑等功能使用各自的柔和强调色；题目难度、平台等级、完成状态、代码语法与作者指定文字颜色继续保留原有含义。

## Markdown、公式与外部链接

题解、算法笔记及讨论正文支持 Markdown 和 KaTeX 公式。彩色文字可写为 `<span style="color:#c7254e">重点</span>` 或 `<font color="blue">重点</font>`；文字颜色支持合法的颜色名、十六进制、RGB 和 HSL，加粗与链接会继承外层指定颜色。仅保留文字颜色，其他内联样式会被移除。

公式可使用 `$\textcolor{red}{x}$`、`$\color{#12ab34}x$`，局部颜色可用花括号限定范围，例如 `$a+{\color{blue}b}+c$`。颜色在浅色、深色及所有配色方案中按原文保留；代码块中的示例保持原样。

正文中的 HTTP/HTTPS 网页链接由系统浏览器打开，支持哔哩哔哩视频、b23.tv 短链接及其他资料站点；页面内的 `#锚点` 链接留在当前正文内跳转。GitHub 授权仍使用独立的 GitHub HTTPS 授权入口。

## Trick 集

侧边栏的 tricks 以紧凑目录展示标题、作者和简介，按最近更新时间排列。具体内容默认隐藏，点击一行后进入独立阅读页；“返回 Trick 集”或 Esc 返回列表并保留搜索条件和滚动位置。两种列表视图都在标题右侧的「前置算法」栏显示去重后的标签，标签较多时用数量提示，详情仍可查看完整前置；搜索匹配标题、作者、简介与这些标签，按 `/` 可聚焦搜索。正文支持与题解相同的 Markdown、公式及代码块。

“等级排行”按 S（优先掌握）、A（推荐掌握）、B（按需查阅）、C（专题补充）、D（少见场景）、E（备查参考）和未评级分组，同档按最近更新排序。展开「等级说明」可查看每档的评判标准；列表徽章悬停可见对应说明，编辑时也会展示所选等级的含义。推荐等级表示满足前置后值得学习的程度，不等同于算法难度。在排行中手动选择“已学算法”并开启“按已学筛选”，只显示已评级且所有前置都满足的 Trick；没有前置要求的已评级条目仍显示。未评级条目不等于低等级，关闭筛选即可浏览。阅读页用依赖图展示各项前置如何汇入当前 Trick，并显示推荐理由。图中可直接勾选或取消「已学」，进度和排行的「按已学筛选」共用同一状态；失效的前置标为未识别，不会计入进度。仓库管理员可在编辑时设置或清除评级；在支持评级的客户端上，普通作者仍可维护正文，但不会更改已有评级。协作者应先升级到 v1.6.1 再编辑带评级的 Trick，旧客户端保存时可能移除它不识别的评级字段。前置从当前算法目录的算法叶子选取。

使用对当前 GitHub 资料库有写入权限的账号，点击“新增 Trick”填写标题、简介和具体内容；正文可切换预览。发布后保存在当前仓库的 `tricks/<UUID>.md`，其他队员同步后可读；作者身份取自登录账号，不能手工指定。作者可修改、删除自己的 Trick，仓库管理员可管理全部 Trick，删除前会再次确认。更新与删除校验当前文件 SHA；编辑输入按资料库、账号和条目保存在本机草稿中，关闭或 Esc 也会保留；发布成功或点击“丢弃草稿”后清除。遇到 SHA 冲突，可保存草稿并关闭、同步后重新编辑；远端有更新时需先查看最新内容并明确勾选确认，才会用草稿更新最新版本。自定义 Gitea 资料库目前仅支持公开读取。

## 算法笔记

知识树采用最新整理的目录：左侧及分类卡片显示简短名称，点开后右侧标题显示完整名称，历史节点关联继续保留。目录只负责分类与子节点导航，不存放笔记、不设置难度；同时代表具体算法的原目录保留原位置和笔记，另开同名算法子节点承载具体学习范围及难度。难度筛选只统计具体算法与知识点，目录仅作为路径保留。

输入关键词、选择难度或属性只调整搜索条件；点击“搜索”或在搜索框按回车后，下方目录和笔记结果才统一刷新。“清除筛选”可立即恢复全部内容。搜索支持简短名、完整名、旧别名、路径、笔记标题、标签、作者及正文；多个词需同时命中，名称准确匹配优先。大小写、全半角、常见空格与连接符差异可兼容。

仓库管理员可点击任意节点旁的小“＋”，或右侧详情的“添加算法”，选择新增目录或算法，填写简短名称、完整名称和可选说明范围，只有算法需要选择难度。新增项保存到当前资料库，并随同步与本机缓存恢复；给已有算法添加子项时，原节点保留为目录，算法及难度移入同名子节点。服务端每次保存均核验管理员权限，普通写入权限不能修改知识树。并发修改发生冲突时保留表单，先同步后重试。

算法笔记顶部可切换“知识树 / 学习路线”。学习路线以初窥、入门、基础、进阶四阶段关系图展示 33 个知识范围与 38 条连接，阶段分别用绿、蓝、金、红区分；默认适应窗口，可切换 100%、手动缩放、搜索或列表视图，窄屏可在图内横向浏览并正常纵向滚动。虚线节点表示可以在补题遇到时再学的内容，并不代表更低等级。

学习路线中的范围节点作为目录，只显示 Markdown 简介与具体知识点入口；进入实际叶子后统一显示“简介、精选笔记、全部笔记”，全部笔记剔除精选，公开与个人范围一致。管理员可编辑简介并设置多篇精选，普通成员只读；目标、注意、混练、知识关系和题单说明统一写入 Markdown 简介。原题单和当前关注记录继续保留。知识树的“仅看已有笔记”按当前范围筛选；无条件重新进入或清除筛选恢复嵌套收起，有条件时继续展开命中路径。

旧闯关记录不会被清除：完成状态、任务、题单和其他未知字段继续保留在原记录中。当前关注写入同一学习记录的 `roadmapFocus` 字段；首次从 GitHub 旧记录读取时保留原键并复制内容，自定义服务不接管来源不明的旧记录。学习路线不提供打卡、完成率或关卡任务；原公共课程编排数据仍用于资料关联与兼容，旧关卡编排入口不再出现在路线界面。

## Linux 与 macOS

源码构建使用 Node.js 24 和 pnpm，安装依赖后运行 `pnpm start`。在目标系统执行 `pnpm dist`，默认按本机平台及架构打包；可用 `QMX_ARCH=x64` 或 `QMX_ARCH=arm64` 选择架构。Linux 生成 tar.gz，macOS 生成 DMG 和 ZIP；0.4.0 起在 Releases 提供这些系统的下载文件。

Linux 解压完整目录后运行 `./QMX-Notebook`，必要时先赋予可执行权限。保持 Electron 沙箱启用，不建议以 root 运行；登录凭据加密需要系统钥匙环（如 GNOME Keyring/KWallet）。系统凭据加密不可用时会提示，不能保证所有桌面发行版都支持登录持久化。

macOS 将 DMG 中的应用拖入“应用程序”再运行。当前构建未签名和公证，系统可能拒绝打开；维护者需配置 Apple 签名与公证后再正式分发。Intel 选择 x64，Apple Silicon 选择 arm64。

个人数据默认由 Electron 保存：Linux 为 `$XDG_CONFIG_HOME/qmx-acm-notebook`（通常 `~/.config/qmx-acm-notebook`），macOS 为 `~/Library/Application Support/qmx-acm-notebook`，不会因替换程序包自动删除。

更新影响：Windows 保持现有签名文件更新链路；Linux 使用相同签名清单及应用包，在可写、非符号链接的解压目录内备份替换并重启，不会安装 Windows EXE。macOS 可以检查更新，但禁止自动改写应用包，以免破坏代码签名；出现新版提示后需手动安装完整应用。文件升级不替换 Electron 运行时，运行时版本不匹配仍需完整安装包。

## 首次设置与代码仓库配置

未登录也可查看公开资料、保存和编辑未绑定账号的本地题解。默认资料库保持 GitHub 的 `qmx-acm-data/2026`，已有仓库设置保留。设置中的“题解仓库管理”支持添加、删除和选择仓库，顶部下拉框可快速切换，切换后自动同步。缓存按服务地址与仓库路径隔离。

- **GitHub**：服务地址留空或填写 `https://github.com`，仓库填写 `owner/repo`。GitHub 登录与授权写入仅用于 GitHub。
- **Gitea 公开仓库**：填写 HTTP/HTTPS 服务地址和 `owner/repo`，也可使用以 `/api/v1` 结尾的 API 地址。内置校内示例 `http://172.25.5.128:3000`、`ctguacm/2026`，需在对应网络中使用。当前自建服务只支持匿名读取，不会转发 GitHub 凭据；不支持 GitLab API、私有仓库认证和自建服务写入。

浏览器预览可运行 `pnpm serve:web`，默认仅监听 `127.0.0.1:3001`。需在局域网访问时显式设置 `HOST=0.0.0.0`；服务器同步仅允许预设 GitHub/校内来源，可通过逗号分隔的 `SYNC_ALLOWED_ORIGINS` 显式配置允许的服务来源。浏览器本地保存和桌面数据各自独立。

0.3.3 起内置队伍公开 OAuth Client ID，队员无需注册 OAuth App 或填写 Client ID；旧设置缺失、为空或无效类型时自动使用队伍配置。点击左下角账号入口，选择登录，在 [GitHub 官方设备授权页面](https://github.com/login/device)输入客户端显示的验证码并授权。每人仍使用自己的 GitHub 账号。Linux 客户端使用系统钥匙环保存登录；GNOME/KDE 保留系统检测，在 niri、sway 等未自动识别后端的桌面默认尝试 libsecret，需要安装并运行兼容的 Secret Service（如 gnome-keyring）。使用 KWallet 时可通过 Chromium 的 `--password-store=kwallet6`（按已安装版本选择）指定后端，显式设置会被保留。设置中的“高级：自定义 GitHub 登录应用”仅供自建应用使用，清空保存恢复默认。不要填写 GitHub 密码、Client Secret 或个人 Token。

账号页显示昵称、用户名、唯一用户 ID 和当前资料库权限，可刷新权限、退出及切换账号。昵称只用于展示，归属按唯一用户 ID 判断，改 GitHub 用户名不会转移题解归属。头像由主进程从 GitHub 获取后以本地数据展示。

队员需要资料库写入权限；团队约定可分配 Admin，但 Write 也足以管理 Markdown 文件。登录授权采用 `public_repo`，权限涉及用户可操作的公开仓库，不能仅限一个仓库。组织 OAuth 策略和默认分支保护也可能限制写入。没有权限时会提示联系管理员，不会自动改走 Issue 或 PR。

## 检查更新

每次启动客户端会在后台检查一次更新，发现新版时显示可关闭的简洁提示。可以选择“稍后再说”、右上角关闭或按 Esc，只有点击“立即更新”才会下载并升级。离线或检查失败时不弹窗打断；正在编辑或打开其他弹窗时，提示会等当前操作结束后显示。

在左下角账户界面查看当前版本，点击“检查更新”。无需登录 GitHub。0.3.4 起，客户端从官方源码仓库读取签名更新清单，将分支固定到同一提交后下载清单中列出的程序文件，不再通过 Release 安装包执行后续更新。

0.3.5 起优先通过 GitHub Contents API 下载固定提交中的清单和应用包；网络异常时依次尝试固定提交的备用来源，并继续验证相同的签名与哈希。请求有超时和有限重试。若已安装 0.3.4 且检查更新提示 `fetch failed`，请从 Releases 下载 0.3.5 安装包，关闭客户端后覆盖安装到原目录，无需卸载或删除个人数据。

发现更高版本后，先保存本地内容，验证清单的 Ed25519 签名。1.1.0 起，在本机应用包与差分基础哈希完全匹配时，优先下载独立签名清单指定的差分补丁，在临时目录重建完整新版并验证大小和 SHA-256；界面显示补丁下载量与完整包大小。没有适用补丁、文件不匹配或补丁失败时，自动回退下载完整 `resources/app.asar`。本地记录、设置、登录信息及公共缓存备份到 `%APPDATA%\qmx-acm-notebook\backups\pre-update-…`。独立更新进程等待客户端退出，备份旧程序，替换并再次校验新程序，然后自动重启。快捷方式和个人数据目录保留。

备份失败、签名不匹配、下载损坏或路径不安全会中止更新。替换失败时尝试恢复旧程序；中断事务会在下次启动时检查恢复。成功事务确认后清理下载、事务暂存包和安装目录中的旧应用副本，完整且通过哈希校验的个人数据备份保留最近两份，小型升级回执保留最近三份；未完成事务、损坏或不认识的备份不会擅自删除。运行中的下载通过进程标记保护；旧版没有标记的历史下载在至少 24 小时后清理。备份包含私人内容及加密登录信息，不要分享。差分与完整包均不重复下载 Electron 运行时。差分下载量取决于实际变化；发布工具只提供比完整包小至少 10% 的补丁。1.0.0 及更早版本尚无补丁重建能力，首次升级到 1.1.0 仍需完整应用包，装上新版后后续兼容更新才会优先使用差分。

清单要求 Electron 运行时版本完全匹配；未来运行时升级时需手动下载新版安装包。Windows 与 Linux 的便携目录也支持签名文件更新，不需要卸载程序；源码运行模式不能覆盖升级。1.0.0 及更早版本仍含有拒绝便携升级的旧检查，必须先退出旧客户端，用修复后的完整便携包覆盖原目录一次（或使用新版安装程序）；新版代码无法在旧版执行该检查之前修复旧版自身。保留个人数据目录即可，之后使用修复后的文件更新流程。

## 本地与 GitHub 题解操作

| 记录 | 保存与修改 | 删除 |
| --- | --- | --- |
| 仅本地 | 只保存当前 Windows 用户的数据，不请求 GitHub | 确认后只移除本机记录 |
| 已上传 | 直接创建或更新资料库中的同一个 Markdown 文件 | 确认仓库和路径后删除 GitHub 当前文件 |

已有题解记录、草稿、收藏和复习状态继续保留。个人收藏不再展示旧版讨论 Issue，旧讨论不计入导航收藏数量。

新建题解填写题目字段和完整 Markdown 正文，选择仅本地保存或上传。本地保存后直接打开题解详情，可继续编辑、删除或收藏；收藏后可从“个人收藏”再次访问。公共题库详情中的小按钮“＋ 本地题解”会打开当前账户已有的同题本地记录，或带入题目名称、链接、平台及难度新建本地草稿；公共题解正文不会被复制。无需仓库写入权限即可本地保存。公共题库仍只显示已上传的正式题解，上传或更新成功后返回公共题库并选中该题解。上传自动记录真实登录用户 ID，客户端只给本人题解提供在线编辑、删除入口。删除文件会保留 Git 提交历史，并非抹除历史。

本地记录在登录状态创建时绑定当前用户 ID；退出或切换账号不会把它转移给新账号。未登录创建的记录初次上传时需确认绑定当前账号。同一 Windows 用户目录中的本地数据不是账号间的安全隔离空间；共享电脑建议使用不同 Windows 账号。

编辑线上文件会保持原路径并携带读取时的 SHA 版本号。远端已变化时拒绝覆盖，先复制保留当前编辑内容，再同步重新打开。网络超时可能已经写入成功，先同步确认；稳定的记录 ID 可让同一内容重试识别已存在文件，避免重复创建。失败时不会关闭编辑窗口。

旧版只有作者昵称的文件可以阅读，但不能据此自动认领。需要维护者核实后补充 `author_id`；不把管理员身份自动当成原作者。旧版 PR 投稿副本显示为已投稿副本，不自动转成新投稿，请先处理原 PR。

## 同步范围

- **正式题库**：默认分支 `problems/`、`algorithms/` 下的 Markdown 文件。这里的“正式”表示已经写入资料目录，不表示经过额外审核；新版直接提交不创建 Issue、Fork 或 PR。
- **旧版 Issues 缓存**：继续同步普通 Issues，包括打开和已关闭的记录；旧讨论不在个人收藏展示，PR 不混入缓存。
- **本地题解**：保留未绑定或归属当前账号的本地题解、草稿与收藏，不随同步上传。其他账号的绑定本地记录不会转移归属。
- **不抓取**：未合并 PR 的题解、其他分支和 Fork 文件，以及其他目录内的文件。

同步会移除远端已删除题解的缓存，不会用旧版线上本地副本重新补回。私人记录、草稿、收藏、复习状态不随同步上传；同步不是逐字实时协作，其他设备需再次同步。

匿名 API 常见额度为每 IP 每小时 60 次，登录后通常为每用户每小时 5000 次，受 GitHub 政策及其他应用共享用量影响。正文按 SHA 缓存并分页读取，避免频繁同步。额度耗尽时，界面横幅会提供「使用 GitHub 登录」入口，授权完成后自动重试同步；登录失效时也会提示重新授权。授权对话框可复制链接并优先用 Chrome 打开，设置界面也提供登录入口。

## Markdown 格式

数学公式与混排写法见[Markdown 与 LaTeX 数学公式](MARKDOWN_MATH.md)，包含常用定界符、矩阵、对齐、表格内公式及支持范围。

新版题解保留兼容字段，并自动添加身份与记录 ID：

```yaml
---
schema: 2
pid: CF1A
title: Theatre Square
platform: CF
tags: [数学]
author: github-login
author_id: 123456
client_id: 12345678-1234-4234-8234-123456789abc
problem_url: https://codeforces.com/problemset/problem/1/A
updated_at: '2026-11-02T12:00:00.000Z'
---
```

`author_id` 与作者由登录身份确定，不能通过编辑昵称冒充。旧文件的 `date`、其他自定义字段继续可读，更新会保留未知元数据。正文完整编辑，避免反复修改导致题解章节重复。CF rating 和其他平台 difficulty 保留平台原生标准，不自动抓取、不跨平台换算。

代码块使用 Prism 做语法高亮，支持 C/C++、Python、Java、Go、Rust 等语言；配色跟随界面风格，未标注或未支持的语言保持等宽纯文本。代码字号可在设置中用滑块调整（10–18px），也可开启代码行号。

启动默认进入紧凑主页。左侧导航提供主页、tricks、公共题库、算法笔记和个人收藏入口，默认显示图标，鼠标移入展开，移出收起；点击右向小三角固定展开，再点击左向小三角恢复悬浮模式，固定偏好会在重启后保留。键盘聚焦导航也会展开，离开后收起。tricks 已提供紧凑目录与点击后阅读的公共技巧集；算法笔记已提供 578 节点的知识树（192 个目录、386 个具体算法或知识点），以及四阶段“学习路线”关系图和原课程资料入口；支持搜索筛选与笔记阅读。笔记格式和权限说明见[算法笔记](ALGORITHM_NOTES.md)。主页不再放置六项快捷入口。

主页顶部的「比赛提醒」从洛谷、Codeforces、AtCoder、牛客的官方赛程读取比赛，四个平台分别缓存后汇总在同一个提醒框中；每个平台最多显示最近三场未结束比赛。时间统一为北京时间，倒计时每秒更新，开赛后显示距结束时间，结束后移除。比赛以紧凑横条展示，点击比赛名称或平台标签可在浏览器打开对应官方页面，无需 GitHub 登录。AtCoder 比赛在名称旁显示 ABC、ARC、AGC、AHC 类型标签，恢复选择列表中也会保留。每场比赛同时显示官方赛时；点击「不参加」会立即隐藏该场比赛，并保存到本机偏好，后续刷新或重启不会再次显示。可点击提醒框右上角的「已隐藏 N 场 · 恢复」，在列表中勾选需要恢复的比赛后确认；未勾选的比赛继续隐藏。

赛程独立缓存在本机，启动先显示缓存，再后台更新；主页可点击「刷新赛程」，自动刷新间隔为 10 分钟。同一平台请求至少间隔 1 分钟，平台限制请求时会延后重试。获取失败保留上次成功的数据，并标明更新时间，实际安排以官方为准。洛谷及牛客展示官方赛程列表提供的近期比赛，不包含平台全部历史或私有比赛。

代码块右上角提供「复制」和「格式化」按钮：复制会保留当前显示的代码文本；格式化由主进程的 clang-format（C/C++/Java/JS/TS/C#/Objective-C）、Ruff（Python）和 rustfmt（Rust，支持 `rust`/`rs` 标记）离线完成，完成后按已加载语言重新高亮。格式化只改变本次阅读中的显示，可复制结果到编辑器保存，原题解不会自动改写。未标注或不支持的语言禁用格式化；超过 200,000 字符的代码会提示拒绝格式化。字号和行号可先预览，点击保存后持久化，关闭设置会撤销未保存的预览。

## 数据安全与备份

Windows 个人数据通常在 `%APPDATA%\qmx-acm-notebook`，便携版也使用这个目录；Linux 与 macOS 的路径见上文平台说明。`local.json` 保存本地记录、草稿和复习状态，`planner.json` 保存本机待做题单与学习任务，`platforms.json` 保存平台绑定与数据快照，`cache.json` 保存公开缓存，`auth.json` 保存加密凭据。题单与任务属于当前设备和系统用户，切换 GitHub 账号或资料库不会切换这份计划，不会随同步上传 GitHub。

应用内升级前的个人数据备份包含 `planner.json`。手动备份题单与任务时，先退出客户端，再复制该文件到安全位置；恢复前同样退出客户端并保留原文件。设置中的“导出本地数据”只导出 `local.json` 对应内容，不包含题单与任务，不能替代 `planner.json` 备份；尚未提供界面导入，可由维护者协助恢复。不要分享整个数据目录或包含凭据的升级备份。

GitHub 请求在 Electron 主进程执行，页面拿不到令牌。登录信息通过 Windows 凭据能力和 Electron `safeStorage` 加密；退出清除本机登录信息，远端撤销授权请访问 [GitHub 应用设置](https://github.com/settings/applications)。安装包不内置管理员凭据。

Markdown 经 DOMPurify 清洗；页面禁止网络连接和远端正文图片，外链只允许受支持平台及 GitHub 的 HTTPS 地址。客户端的本人操作限制是产品行为；拥有仓库 Admin/Write 的用户仍能在 GitHub 外部修改其他文件，客户端不改变 GitHub 权限模型。

## 验收与当前限制

新版内置队伍 OAuth 配置；应用负责人仍需保持 Device Flow 启用并批准必要的组织访问。不同队员的真实账号登录和权限需各自验收。维护工具的 GitHub CLI 登录不能代替客户端 OAuth 验收。

暂不支持图片附件、私人数据跨设备同步、备份界面导入、自动认领旧版无用户 ID 文档。直接打开源码的页面是浏览器演示，演示不会向 GitHub 投稿。
