# 使用指南

[项目首页](../README.md) · [维护与发布](RELEASING.md)

## 安装和启动

在[客户端 Releases](https://github.com/qmx-acm-data/qmx-acm-notebook/releases)下载对应版本的 `QMX-Notebook-Setup-<version>.exe`，运行后按提示安装。安装无需管理员权限，会创建桌面和开始菜单快捷方式，卸载保留个人数据。浏览器下载本身不会创建快捷方式。

便携版需解压整个目录，运行「启动.cmd」，不能只复制 exe。普通启动失败时可试「兼容启动.cmd」；兼容模式另加 `--no-sandbox`，会降低 Chromium 进程隔离能力。当前验证机器曾需要兼容模式。程序未签名，Windows 可能提示未知发布者，请核对来源。GitHub 的 Source code 压缩包是源码，不是安装包。

## 平台账号与主页概览

在设置的“竞赛平台账号”点击“绑定账号”，粘贴对应平台的 HTTPS 个人主页链接。验证成功后仅显示用户名，再次点击可更换或解除绑定。绑定与公开数据快照仅保存在本机，独立于 GitHub 登录，不需要平台密码或 Cookie。

主页采用紧凑布局，集中显示比赛提醒、待做题目、学习任务和“做题与比赛总览”，不再显示六项快捷入口。tricks、公共题库、算法笔记与个人收藏通过侧边栏访问。总览汇总总解题、总提交及最近比赛；右上角选择平台只切换每日解题、总解题、总提交和最近一场比赛，两张 Rating 图、账号列表和下方比赛历史保持汇总显示。刷新按钮按当前选择更新，展开统计可增大图表和记录区域。Codeforces 和 AtCoder 各有完整公开 Rating 历史折线图，悬停或聚焦圆点查看比赛信息。总解题为各平台题数相加，同题跨平台不去重；未知字段不视为零，合计附带数据覆盖率。洛谷按主页“提交”栏原值计入总提交，来源说明保留平台显示口径。

每日热度图按北京时间汇总各平台：CF、AtCoder、牛客在取得完整公开提交历史后，按每题首次 AC 日期去重；洛谷采用官方每日通过题数，覆盖最近180天截至昨日，数据非实时，不能保证与首次AC口径相同。选择最近一年或上一年，鼠标悬停、点击或键盘聚焦日期时弹出两行浮窗，显示日期与总通过数；覆盖不完整时标记“已知”。Rating 圆点、最近比赛和比赛记录也会弹出浮窗，第一行加粗比赛名，其后显示 Rating 变化（若公开），最后显示赛时通过题数/总题数（若可核实，例如3/7）；不使用补题通过数代替赛时通过。完整区间外显示未知。力扣若只能取得最近一段 AC 列表，不据此推算全年热图；公开通过数和提交数均为零时显示真实空日历。

重启先恢复本机缓存，刷新失败保留旧数据与时间。Codeforces 超过20,000条提交、AtCoder Problems超过20,000条或时间边界不完整、牛客超过20页时不以截断历史计算完整日历。AtCoder Problems为第三方来源，可能延迟；牛客只统计公开编程练习；洛谷只展示主页最近评定比赛；力扣国服与国际服分别读取公开资料，无公开竞赛积分不代表从未参赛。来源及限制可展开面板底部说明。

应用源码与安装包不包含默认个人绑定。全新用户的五个平台均显示“绑定账号”；验收时使用的个人链接和数据只保存在独立测试目录，不进入发布资源。

## 待做题目与学习任务

“待做题目”用于收集稍后练习的题目：粘贴题目链接，可同时粘贴名称，也可单独填写可选名称；未填写名称时按链接生成题号或路径名称。支持 Codeforces（含 contest/gym）、AtCoder、洛谷、牛客、力扣国服/国际服、Hydro 和 AcWing 的官方题目 HTTP/HTTPS 链接；不接受任意网页、含凭据或自定义端口的地址。同一链接已在未完成题单中时会提示重复，点击题目名称可打开原题。

“学习任务”填写标题即可添加，截止时间可选。点击截止时间按钮打开日历弹窗，可选择日期与时刻，也可使用今天、明天、+7天或清除；确定后应用，取消或按 Esc 放弃本次选择。截止时间按本机时区填写和显示，与比赛提醒统一使用北京时间的规则不同；有截止时间的未完成任务按时间先后排列，逾期会标记。

点击任务标题打开只读详情，查看完整标题、截止时间与任务说明；修改标题、截止时间或补充说明时点击该行“编辑”。补充说明最多 2000 字，任务标题和题目名称最多 180 字。题目与任务均可勾选完成、取消完成或确认删除；已完成内容在单独分组中保留。两类列表可独立收起并滚动查看，每类最多保存 500 项。

题单与任务保存在当前设备、当前系统用户数据目录的 `planner.json`，无需 GitHub 登录；切换 GitHub 账号或资料库仍使用同一份计划，不按 GitHub 账号隔离，也不上传或同步到 GitHub。重启恢复已保存内容，备份方法见[数据安全与备份](#数据安全与备份)。

## 搜索与筛选

搜索支持题号（如 `P1001`、`CF 1900 D`）、题目链接和多个关键词。空格分隔的词需要同时匹配，可跨标题、标签和正文命中；精确题号优先，其次按相关程度排序，无搜索时按更新时间排序。

平台、标签、作者展开后均可多选，并可在组内查找；同组条件任选其一，不同组同时满足。点击已选条件右侧的 × 可移除，点击“重置”清空搜索及全部条件。

难度面板一次选择 CF Rating、洛谷难度或其他原生难度体系，区间包含端点，切换体系会清除上一组条件，不做跨平台换算；其他平台的原生难度可多选。非洛谷平台也可独立保存补充洛谷难度，并参与洛谷难度筛选。启用难度条件后无对应难度的题目不会命中。最低值高于最高值会提示调整。颜色按 Codeforces 色阶、洛谷原生等级及 LeetCode 简单/中等/困难对应，深色主题使用适配的可读色值。

## Markdown、公式与外部链接

题解、算法笔记及讨论正文支持 Markdown 和 KaTeX 公式。彩色文字可写为 `<span style="color:#c7254e">重点</span>` 或 `<font color="blue">重点</font>`；文字颜色支持合法的颜色名、十六进制、RGB 和 HSL，加粗与链接会继承外层指定颜色。仅保留文字颜色，其他内联样式会被移除。

公式可使用 `$\textcolor{red}{x}$`、`$\color{#12ab34}x$`，局部颜色可用花括号限定范围，例如 `$a+{\color{blue}b}+c$`。颜色在浅色、深色与卡片风格中按原文保留；代码块中的示例保持原样。

正文中的 HTTP/HTTPS 网页链接由系统浏览器打开，支持哔哩哔哩视频、b23.tv 短链接及其他资料站点；页面内的 `#锚点` 链接留在当前正文内跳转。GitHub 授权仍使用独立的 GitHub HTTPS 授权入口。

## 算法笔记

知识树采用最新整理的目录：左侧及分类卡片显示简短名称，点开后右侧标题显示完整名称，历史节点关联继续保留。目录只负责分类、说明和笔记，不设置难度；同时代表具体算法的原目录保留原位置和笔记，另开同名算法子节点承载具体学习范围及难度。难度筛选只统计具体算法与知识点，目录仅作为路径保留。

输入关键词、选择难度或属性只调整搜索条件；点击“搜索”或在搜索框按回车后，下方目录和笔记结果才统一刷新。“清除筛选”可立即恢复全部内容。搜索支持简短名、完整名、旧别名、路径、笔记标题、标签、作者及正文；多个词需同时命中，名称准确匹配优先。大小写、全半角、常见空格与连接符差异可兼容。

仓库管理员可点击任意节点旁的小“＋”，或右侧详情的“添加算法”，选择新增目录或算法，填写简短名称、完整名称和可选说明范围，只有算法需要选择难度。新增项保存到当前资料库，并随同步与本机缓存恢复；给已有算法添加子项时，原节点保留为目录，算法及难度移入同名子节点。服务端每次保存均核验管理员权限，普通写入权限不能修改知识树。并发修改发生冲突时保留表单，先同步后重试。

算法笔记顶部可切换“知识树 / 闯关学习”。闯关学习采用 B3 阶段弹窗，共 15 章（第0—14章）、169 关。第0章首关“总览算法竞赛”为入门导览，关联知识树“算法竞赛经验与游记”目录，不设置题目难度；原第1—14章按先广后深的综合做题能力安排，第1—2章引入常用 STL，各章第 4、8 关为混练、第 12 关为综合挑战。具体关卡关联知识树节点，显示节点实际学习难度；CF 选题窗口和洛谷标签独立显示，不作等价换算。点击关联知识点可进入知识树，知识点详情可返回对应学习关卡。每关保留具体算法标题，并附初识、进阶或综合应用的短描述；详情用简洁语言串联已有基础与后续方法。“把知识连成线”可直接回顾或延伸同一主线上的关卡，这些联系用于理解知识结构，不是新增锁关条件。

“开始学习”和“记录本关完成”保存本机进度，可记录练习链接及复盘，也可撤销完成。记录按资料库和当前账号分别保存到 `local.json`，未登录进度单独保留；不会自动同步到队友设备。徽章由真实记录点亮，完成记录不等同自动评测通过。相关公开笔记展示实际贡献者，“复制互助卡”仅复制文本供自行交流。真实训练题单尚未绑定。

## Linux 与 macOS

源码构建使用 Node.js 24 和 pnpm，安装依赖后运行 `pnpm start`。在目标系统执行 `pnpm dist`，默认按本机平台及架构打包；可用 `QMX_ARCH=x64` 或 `QMX_ARCH=arm64` 选择架构。Linux 生成 tar.gz，macOS 生成 DMG 和 ZIP；0.4.0 起在 Releases 提供这些系统的下载文件。

Linux 解压完整目录后运行 `./QMX-Notebook`，必要时先赋予可执行权限。保持 Electron 沙箱启用，不建议以 root 运行；登录凭据加密需要系统钥匙环（如 GNOME Keyring/KWallet）。系统凭据加密不可用时会提示，不能保证所有桌面发行版都支持登录持久化。

macOS 将 DMG 中的应用拖入“应用程序”再运行。当前构建未签名和公证，系统可能拒绝打开；维护者需配置 Apple 签名与公证后再正式分发。Intel 选择 x64，Apple Silicon 选择 arm64。

个人数据默认由 Electron 保存：Linux 为 `$XDG_CONFIG_HOME/qmx-acm-notebook`（通常 `~/.config/qmx-acm-notebook`），macOS 为 `~/Library/Application Support/qmx-acm-notebook`，不会因替换程序包自动删除。

更新影响：Windows 保持现有签名文件更新链路；Linux 使用相同签名清单及应用包，在可写、非符号链接的解压目录内备份替换并重启，不会安装 Windows EXE。macOS 可以检查更新，但禁止自动改写应用包，以免破坏代码签名；出现新版提示后需手动安装完整应用。文件升级不替换 Electron 运行时，运行时版本不匹配仍需完整安装包。

## 首次设置与 GitHub 登录

未登录也可查看公开资料、保存和编辑未绑定账号的本地题解。默认资料库是 `qmx-acm-data/2026`，程序源码库是 `qmx-acm-data/qmx-acm-notebook`。

0.3.3 起内置队伍公开 OAuth Client ID，队员无需注册 OAuth App 或填写 Client ID；旧设置缺失、为空或无效类型时自动使用队伍配置。点击左下角账号入口，选择登录，在 [GitHub 官方设备授权页面](https://github.com/login/device)输入客户端显示的验证码并授权。每人仍使用自己的 GitHub 账号。Linux 客户端使用系统钥匙环保存登录；GNOME/KDE 保留系统检测，在 niri、sway 等未自动识别后端的桌面默认尝试 libsecret，需要安装并运行兼容的 Secret Service（如 gnome-keyring）。使用 KWallet 时可通过 Chromium 的 `--password-store=kwallet6`（按已安装版本选择）指定后端，显式设置会被保留。设置中的“高级：自定义 GitHub 登录应用”仅供自建应用使用，清空保存恢复默认。不要填写 GitHub 密码、Client Secret 或个人 Token。

账号页显示昵称、用户名、唯一用户 ID 和当前资料库权限，可刷新权限、退出及切换账号。昵称只用于展示，归属按唯一用户 ID 判断，改 GitHub 用户名不会转移题解归属。头像由主进程从 GitHub 获取后以本地数据展示。

队员需要资料库写入权限；团队约定可分配 Admin，但 Write 也足以管理 Markdown 文件。登录授权采用 `public_repo`，权限涉及用户可操作的公开仓库，不能仅限一个仓库。组织 OAuth 策略和默认分支保护也可能限制写入。没有权限时会提示联系管理员，不会自动改走 Issue 或 PR。

## 检查更新

每次启动客户端会在后台检查一次更新，发现新版时显示可关闭的简洁提示。可以选择“稍后再说”、右上角关闭或按 Esc，只有点击“立即更新”才会下载并升级。离线或检查失败时不弹窗打断；正在编辑或打开其他弹窗时，提示会等当前操作结束后显示。

在左下角账户界面查看当前版本，点击“检查更新”。无需登录 GitHub。0.3.4 起，客户端从官方源码仓库读取签名更新清单，将分支固定到同一提交后下载清单中列出的程序文件，不再通过 Release 安装包执行后续更新。

0.3.5 起优先通过 GitHub Contents API 下载固定提交中的清单和应用包；网络异常时依次尝试固定提交的备用来源，并继续验证相同的签名与哈希。请求有超时和有限重试。若已安装 0.3.4 且检查更新提示 `fetch failed`，请从 Releases 下载 0.3.5 安装包，关闭客户端后覆盖安装到原目录，无需卸载或删除个人数据。

发现更高版本后，先保存本地内容，验证清单的 Ed25519 签名。1.1.0 起，在本机应用包与差分基础哈希完全匹配时，优先下载独立签名清单指定的差分补丁，在临时目录重建完整新版并验证大小和 SHA-256；界面显示补丁下载量与完整包大小。没有适用补丁、文件不匹配或补丁失败时，自动回退下载完整 `resources/app.asar`。本地记录、设置、登录信息及公共缓存备份到 `%APPDATA%\qmx-acm-notebook\backups\pre-update-…`。独立更新进程等待客户端退出，备份旧程序，替换并再次校验新程序，然后自动重启。快捷方式和个人数据目录保留。

备份失败、签名不匹配、下载损坏或路径不安全会中止更新。替换失败时尝试恢复旧程序；中断事务会在下次启动时检查恢复。成功事务确认后清理下载、事务暂存包和安装目录中的旧应用副本，完整且通过哈希校验的个人数据备份保留最近两份，小型升级回执保留最近三份；未完成事务、损坏或不认识的备份不会擅自删除。运行中的下载通过进程标记保护；旧版没有标记的历史下载在至少 24 小时后清理。备份包含私人内容及加密登录信息，不要分享。差分与完整包均不重复下载 Electron 运行时。差分下载量取决于实际变化；发布工具只提供比完整包小至少 10% 的补丁。1.0.0 及更早版本尚无补丁重建能力，首次升级到 1.1.0 仍需完整应用包，装上新版后后续兼容更新才会优先使用差分。

清单要求 Electron 运行时版本完全匹配；未来运行时升级时需手动下载新版安装包。Windows 与 Linux 的便携目录也支持签名文件更新，不需要卸载程序；源码运行模式不能覆盖升级。1.0.0 及更早版本仍含有拒绝便携升级的旧检查，必须先退出旧客户端，用修复后的完整便携包覆盖原目录一次（或使用新版安装程序）；新版代码无法在旧版执行该检查之前修复旧版自身。保留个人数据目录即可，之后使用修复后的文件更新流程。

## 本地与 GitHub 题解操作

| 记录 | 保存与修改 | 删除 |
| --- | --- | --- |
| 仅本地 | 只保存当前 Windows 用户的数据，不请求 GitHub | 确认后只移除本机记录 |
| 已上传 | 直接创建或更新资料库中的同一个 Markdown 文件 | 确认仓库和路径后删除 GitHub 当前文件 |
| 已收藏的旧版 Issue | 从个人收藏阅读及发表评论 | 管理员可永久删除整个 Issue 及其讨论，不影响正式题解文件 |

已有记录、草稿、收藏和复习状态继续保留。旧版 Issue 若已收藏，仍可从个人收藏查看；其中的“永久删除讨论 Issue”仅向当前仓库管理员显示。确认仓库、编号和标题后，会删除 GitHub Issue 及其讨论，不能撤销。组织 Owner 还需在组织设置中允许删除 Issues；若不允许，客户端明确提示且保留记录，不会自动改成关闭 Issue。

新建题解填写题目字段和完整 Markdown 正文，选择仅本地保存或上传。本地保存后直接打开题解详情，可继续编辑、删除或收藏；收藏后可从“个人收藏”再次访问。公共题库详情中的小按钮“＋ 本地题解”会打开当前账户已有的同题本地记录，或带入题目名称、链接、平台及难度新建本地草稿；公共题解正文不会被复制。无需仓库写入权限即可本地保存。公共题库仍只显示已上传的正式题解，上传或更新成功后返回公共题库并选中该题解。上传自动记录真实登录用户 ID，客户端只给本人题解提供在线编辑、删除入口。删除文件会保留 Git 提交历史，并非抹除历史。

本地记录在登录状态创建时绑定当前用户 ID；退出或切换账号不会把它转移给新账号。未登录创建的记录初次上传时需确认绑定当前账号。同一 Windows 用户目录中的本地数据不是账号间的安全隔离空间；共享电脑建议使用不同 Windows 账号。

编辑线上文件会保持原路径并携带读取时的 SHA 版本号。远端已变化时拒绝覆盖，先复制保留当前编辑内容，再同步重新打开。网络超时可能已经写入成功，先同步确认；稳定的记录 ID 可让同一内容重试识别已存在文件，避免重复创建。失败时不会关闭编辑窗口。

旧版只有作者昵称的文件可以阅读，但不能据此自动认领。需要维护者核实后补充 `author_id`；不把管理员身份自动当成原作者。旧版 PR 投稿副本显示为已投稿副本，不自动转成新投稿，请先处理原 PR。

## 同步范围

- **正式题库**：默认分支 `problems/`、`algorithms/` 下的 Markdown 文件。这里的“正式”表示已经写入资料目录，不表示经过额外审核；新版直接提交不创建 Issue、Fork 或 PR。
- **旧版 Issues 缓存**：继续同步普通 Issues，包括打开和已关闭的记录；已收藏内容可从个人收藏阅读，评论按需加载，PR 不混入其中。
- **本地题解**：保留未绑定或归属当前账号的本地题解、草稿与收藏，不随同步上传。其他账号的绑定本地记录不会转移归属。
- **不抓取**：未合并 PR 的题解、其他分支和 Fork 文件，以及其他目录内的文件。

同步会移除远端已删除题解的缓存，不会用旧版线上本地副本重新补回。私人记录、草稿、收藏、复习状态不随同步上传；同步不是逐字实时协作，其他设备需再次同步。

匿名 API 常见额度为每 IP 每小时 60 次，登录后通常为每用户每小时 5000 次，受 GitHub 政策及其他应用共享用量影响。正文按 SHA 缓存并分页读取，避免频繁同步。额度耗尽时，界面横幅会提供「使用 GitHub 登录」入口，授权完成后自动重试同步；登录失效时也会提示重新授权。授权对话框可复制链接并优先用 Chrome 打开，设置界面也提供登录入口。

## Markdown 格式

数学公式与混排写法见[Markdown 与 LaTeX 数学公式](MARKDOWN_MATH.md)，包含常用定界符、矩阵、对齐、表格内公式及支持范围。

新版题解保留兼容字段，并自动添加身份与记录 ID：

```yaml
---
schema: 2
pid: CF1A
title: Theatre Square
platform: CF
tags: [数学]
author: github-login
author_id: 123456
client_id: 12345678-1234-4234-8234-123456789abc
problem_url: https://codeforces.com/problemset/problem/1/A
updated_at: '2026-11-02T12:00:00.000Z'
---
```

`author_id` 与作者由登录身份确定，不能通过编辑昵称冒充。旧文件的 `date`、其他自定义字段继续可读，更新会保留未知元数据。正文完整编辑，避免反复修改导致题解章节重复。CF rating 和其他平台 difficulty 保留平台原生标准，不自动抓取、不跨平台换算。

代码块使用 Prism 做语法高亮，支持 C/C++、Python、Java、Go、Rust 等语言；配色跟随界面风格，未标注或未支持的语言保持等宽纯文本。代码字号可在设置中用滑块调整（10–18px），也可开启代码行号。

启动默认进入紧凑主页。左侧导航提供主页、tricks、公共题库、算法笔记和个人收藏入口，默认显示图标，鼠标移入展开，移出收起；点击右向小三角固定展开，再点击左向小三角恢复悬浮模式，固定偏好会在重启后保留。键盘聚焦导航也会展开，离开后收起。tricks 当前为占位页；算法笔记已提供 578 节点的知识树（192 个目录、386 个具体算法或知识点），以及 15 章、169 关的闯关学习；支持搜索筛选与笔记阅读。笔记格式和权限说明见[算法笔记](ALGORITHM_NOTES.md)。主页不再放置六项快捷入口。

主页顶部的「比赛提醒」从洛谷、Codeforces、AtCoder、牛客的官方赛程读取比赛，四个平台分别缓存后汇总在同一个提醒框中；每个平台最多显示最近三场未结束比赛。时间统一为北京时间，倒计时每秒更新，开赛后显示距结束时间，结束后移除。比赛以紧凑横条展示，点击比赛名称或平台标签可在浏览器打开对应官方页面，无需 GitHub 登录。AtCoder 比赛在名称旁显示 ABC、ARC、AGC、AHC 类型标签，恢复选择列表中也会保留。每场比赛同时显示官方赛时；点击「不参加」会立即隐藏该场比赛，并保存到本机偏好，后续刷新或重启不会再次显示。可点击提醒框右上角的「已隐藏 N 场 · 恢复」，在列表中勾选需要恢复的比赛后确认；未勾选的比赛继续隐藏。

赛程独立缓存在本机，启动先显示缓存，再后台更新；主页可点击「刷新赛程」，自动刷新间隔为 10 分钟。同一平台请求至少间隔 1 分钟，平台限制请求时会延后重试。获取失败保留上次成功的数据，并标明更新时间，实际安排以官方为准。洛谷及牛客展示官方赛程列表提供的近期比赛，不包含平台全部历史或私有比赛。

代码块右上角提供「复制」和「格式化」按钮：复制会保留当前显示的代码文本；格式化由主进程的 clang-format（C/C++/Java/JS/TS/C#/Objective-C）、Ruff（Python）和 rustfmt（Rust，支持 `rust`/`rs` 标记）离线完成，完成后按已加载语言重新高亮。格式化只改变本次阅读中的显示，可复制结果到编辑器保存，原题解不会自动改写。未标注或不支持的语言禁用格式化；超过 200,000 字符的代码会提示拒绝格式化。字号和行号可先预览，点击保存后持久化，关闭设置会撤销未保存的预览。

## 数据安全与备份

Windows 个人数据通常在 `%APPDATA%\qmx-acm-notebook`，便携版也使用这个目录；Linux 与 macOS 的路径见上文平台说明。`local.json` 保存本地记录、草稿和复习状态，`planner.json` 保存本机待做题单与学习任务，`platforms.json` 保存平台绑定与数据快照，`cache.json` 保存公开缓存，`auth.json` 保存加密凭据。题单与任务属于当前设备和系统用户，切换 GitHub 账号或资料库不会切换这份计划，不会随同步上传 GitHub。

应用内升级前的个人数据备份包含 `planner.json`。手动备份题单与任务时，先退出客户端，再复制该文件到安全位置；恢复前同样退出客户端并保留原文件。设置中的“导出本地数据”只导出 `local.json` 对应内容，不包含题单与任务，不能替代 `planner.json` 备份；尚未提供界面导入，可由维护者协助恢复。不要分享整个数据目录或包含凭据的升级备份。

GitHub 请求在 Electron 主进程执行，页面拿不到令牌。登录信息通过 Windows 凭据能力和 Electron `safeStorage` 加密；退出清除本机登录信息，远端撤销授权请访问 [GitHub 应用设置](https://github.com/settings/applications)。安装包不内置管理员凭据。

Markdown 经 DOMPurify 清洗；页面禁止网络连接和远端正文图片，外链只允许受支持平台及 GitHub 的 HTTPS 地址。客户端的本人操作限制是产品行为；拥有仓库 Admin/Write 的用户仍能在 GitHub 外部修改其他文件，客户端不改变 GitHub 权限模型。

## 验收与当前限制

新版内置队伍 OAuth 配置；应用负责人仍需保持 Device Flow 启用并批准必要的组织访问。不同队员的真实账号登录和权限需各自验收。维护工具的 GitHub CLI 登录不能代替客户端 OAuth 验收。

暂不支持图片附件、私人数据跨设备同步、备份界面导入、自动认领旧版无用户 ID 文档。直接打开源码的页面是浏览器演示，演示不会向 GitHub 投稿。
