# 拾题 TypeScript 重构实施计划

本计划细化 [重构基线与约束](TYPESCRIPT_REFACTOR.md)，用于后续逐批实施和验收。当前为计划交付，不代表全面迁移已完成。

## 1. 目标与范围

目标：让功能代码使用明确类型和显式模块依赖，把大型入口按职责拆开，保留 v1.2.4 的全部现有功能和操作流程，并确保开发、测试、打包运行同一套代码。

原计划基线为 v1.2.4；实施时已同步 v1.2.5、主分支提交 `30698d822f4ae345f972b4106b648dda8442a2b6`，包含多仓库管理和连续差分更新。实施分支为 `refactor/typescript-foundation`。若主分支有新功能合入，先记录并纳入新的验收基线，再继续迁移，不能覆盖或漏迁。

本轮不同时更换 UI 框架、测试框架、Electron 运行时、格式化引擎、数据 schema 或更新签名协议。后续确有行为修复需求，独立成批并说明原有行为和目标差异。

功能保持包括：页面文案与布局、DOM/CSS 接口、快捷键和焦点、路由和滚动恢复、排序和默认值、离线回退、错误提示、保存时机、持久化字段、账号/资料库隔离、权限和并发锁、外部链接规则以及升级恢复行为。编译前后源码和归档哈希可以变化；对外数据和用户行为必须兼容。

## 2. 已完成准备与进入条件

计划制定时已完成的准备（现已分别记录为清理与基础提交；首批实施状态见末尾）：

- 清理旧发布包、缓存、未采用原型与过时工具，保留业务源码、测试、文档、生成数据和签名更新文件。
- 固定 TypeScript 5.9.3；严格检查阅读详情 JS 与对应真实接口类型，未启用运行时 TS loader。
- 新增 `typecheck`、`check:refactor`、`test:ui:refactor`，CI 加入类型检查。
- 上一轮验证：409 个单元用例，408 通过，1 个文件符号链接用例因本机权限跳过；12 组现有界面回归全部通过。

实施前处理：

1. 分开记录清理改动与重构基础改动，保留用户使用攻略等未跟踪文稿；检查后再分别提交，避免把文稿或验收产物混入代码提交。
2. 当前依赖目录是指向其他工作区的 junction。建立本分支独立依赖安装，先核对链接本身，再仅移除链接，不能递归删除指向的共享目录。按锁文件安装并验证普通 `pnpm typecheck` 可直接使用本地编译器。上轮在此特殊环境使用固定版本缓存编译器验证过类型，不能将它作为团队安装步骤。
3. 在干净环境复跑基线，记录环境、提交号、通过数、跳过原因和检查范围。检查记录属于执行证据，不把大日志、截图或安装包提交仓库。

## 3. 架构与产物约定

计划引入独立源码区，逐模块搬迁，迁移期间旧代码仍可参与构建：

```text
src/
  shared/                 跨进程/跨界面的领域类型与纯逻辑
    contracts/            IPC 请求、响应、事件类型
    models/               记录、笔记、课程、账户等模型
  renderer/
    app/                  启动、状态、导航、依赖组装
    features/             library / algorithms / planner / contests / platforms / account / updates
    reading/              Markdown、代码工具、阅读详情
    lib/                  小型 DOM 工具等
  main/
    services/             持久化、GitHub、认证、比赛、平台、计划
    ipc/                  按功能注册 handler
    updates/              更新器、差分、恢复与独立 helper
    main.cts
    preload.cts
build/app/                可删除的应用编译产物，Git 忽略
  package.json
  electron/               维持运行时相对路径的 .cjs 产物
  ui/                     HTML、CSS、资源与浏览器脚本
  node_modules/           按现有规则准备的生产依赖
```

这是职责和产物布局约定；首个构建批次需用实际试编译验证，不提前创建大量空文件夹。生成数据继续由已有数据源及生成器维护，禁止手改生成的大型 JS 文件。必要时由构建复制现有生成数据，后续统一调整生成出口。

技术选择：

- Electron 源码使用 `.cts`，NodeNext 输出 `.cjs`；保持原生动态 `import()`，兼容 ESM/WASM 格式化依赖。
- renderer 使用 `.ts` 的显式 import/export。推荐固定版本 esbuild 输出适合 file:// 与现有 CSP 的本地脚本，`tsc` 负责类型检查；先以一个浏览器 IIFE 入口输出验证兼容性，默认不拆运行时 chunks。
- 浏览器、Electron、工具、共享类型分别配置 TS 环境；浏览器不能意外获得 Node 类型或权限。共享层不能依赖 DOM、Electron 或凭据服务。
- 编译和类型检查分开；构建必须等待类型检查通过，不能把 esbuild 转译成功当作类型正确。
- `preload.cjs` 和 `update-helper.cjs` 各自独立产物。前者只用允许的 Electron API，后者只依赖内置模块；类型使用 `import type`。
- 开发与测试统一指向 build/app；打包必须调用构建或校验同一批构建产物。禁止开发用新代码、打包仍复制旧源码。
- 旧全局 API 在迁移期间由薄适配层提供，每迁移完一组调用方就删除对应全局。不得让同一模块初始化两遍。

## 4. 分阶段与批次

依赖顺序：P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7。每个编号为独立可审查提交或 PR；阶段内带字母的批次分别验收。允许发现依赖时先抽出一小批公共类型，不能把多个高风险阶段合并成一次大改。

### P0：固定基线与工作区

范围：清理结果、重构文档、依赖环境、已有检查命令。

任务：

- 完成第 2 节的独立依赖和干净基线；把现有 TS 检查纳入稳定命令。
- 核对全部 preload 方法及事件，与主进程 handler 对照，记录参数、返回值、错误语义和调用方。保留 submit/propose 等旧别名。
- 确认当前 12 组界面回归的覆盖范围；列出尚需单独运行的代码动作、阅读偏好、真实计划持久化和真实账号场景。

验收：锁文件安装成功；现有检查全部通过；未跟踪用户文稿保留；功能基线可追溯。

回退：只撤回基础配置提交，不影响现有 JS 入口和发布包。

### P1：统一编译、启动、测试与打包路径

P1a 构建复制与最小 TS 试迁移：

- 新增编译配置与最小构建脚本，将尚未迁移的 JS、HTML、CSS、生成数据和必要资源复制到 build/app。
- 首先迁移阅读详情这一小模块；构建输出保持页面脚本的加载位置和 API。
- 生产依赖沿用已有递归收集方式，检查格式化器 WASM/二进制资源与第三方库文件完整。

P1b 接入运行入口：

- 将 start、单元测试模块定位、浏览器 UI 定位和 package 暂存输入统一为编译根目录。
- VM 测试保留 require 拦截、进程模拟和关键安全断言；根据编译模块需要补全 CommonJS wrapper。
- 清理构建只操作经核对的 build 目录；显式区分仓库根、构建根、签名候选根，不能依赖编译后变化的 __dirname 猜根目录。
- 为开发构建输出 source map，默认发行产物不附源码和 map。

验收：同一份编译产物能够启动、运行原有检查、生成本地包；源码与构建目录不存在重复模块实例；Windows 真实桌面启动、Markdown/离线格式化、preload IPC 可用。

回退：整批撤回入口和构建改动，恢复旧启动路径。此阶段不激活更新通道。

### P2：共享领域模型与 IPC 契约

P2a 领域数据：

- 按实际解析器和存储定义 LocalRecord / DocumentRecord / IssueRecord / AlgorithmNote，使用 kind 判别联合。
- 分别定义存储格式、归一化领域数据和页面状态；保留历史字段和未知 frontmatter，避免用一个“万能类型”覆盖所有层。
- 定义知识目录/算法节点、课程/章节/关卡、学习进度、账户/权限、计划/比赛/平台统计、更新状态。
- 保留缺失、null、0 和空数组的原有差异；类型不擅自收紧旧数据可接受范围。

P2b IPC：

- 从真实 handler 推导方法名、参数元组、Promise 返回值和进度事件；建立类型化 invoke/注册包装。
- 保留原频道名、错误传播方式、订阅取消函数和同步/异步行为。
- IPC 入参仍在主进程校验，不能因为 renderer 有类型而信任它。

验收：renderer/main/preload 使用同一类型来源；通过有意义的类型用例证明错误频道/参数被拒绝；全部原 IPC 行为及隔离检查通过。

回退：撤回对应契约接入层，保留原频道实现；不迁移磁盘数据。

### P3：纯逻辑与阅读能力

P3a 搜索、标签、目录处理：迁移搜索、平台与难度映射、目录 hydrate/评分，保持别名和排序；主进程共享逻辑移到纯共享模块。

P3b Markdown：迁移公式 token、表格处理、颜色过滤，保持 Marked → DOMPurify → KaTeX 的实际处理语义；保留宏作用域、错误隔离、链接与代码文本行为。

P3c 阅读组件：迁移阅读详情、代码复制/格式化/高亮和阅读偏好，按现有 DOM/CSS 工作，不改页面设计。

验收：搜索/目录/公式/表格单测，相关 UI 回归及 code-actions、code-highlight、reading-prefs；三主题、390px、Esc/焦点/滚动；格式化失败保留原始代码。

回退：逐模块撤回；每个模块只保留一份运行实现，不能长期双写新旧结果。

### P4：拆分 renderer 大型入口

顺序：P4a 状态与启动 → P4b 题库与编辑器 → P4c 算法学习 → P4d 主页模块 → P4e 账户与更新。

| 批次 | 拆分职责 | 行为保持重点 |
| --- | --- | --- |
| P4a | payload 归一化、应用状态、导航、主题、侧栏、toast、启动组装 | 默认页、加载顺序、事件只绑定一次、销毁与重建、演示模式 |
| P4b | 搜索筛选、列表、题解详情、编辑器、草稿、收藏/复习、评论 | 私有隔离、同题本地记录、自动保存队列、失败回滚、上传/删除确认 |
| P4c | 知识树、笔记管理、章节与关卡、学习进度、嵌套阅读 | 节点/别名/关卡 ID、原进度键、精选排序、路径与返回、账号资料库作用域 |
| P4d | 比赛、平台、计划、截止日期、主页组装 | 定时器清理、统计缺失值、缓存/节流、截止时间、比赛不参加与恢复 |
| P4e | 账户设置、认证进度、更新状态与启动提示 | 取消/重试、按钮锁、编辑器关闭前延迟提示、保存后升级、旧 bridge 兼容 |

模块通过窄接口传入所需状态、操作和回调，避免把全局大状态整体传遍所有模块。应用入口只负责实例创建、依赖连接、初次加载与销毁；不设人为行数指标，但不得保留大段具体功能处理。

验收：每批运行相关组；阶段结束跑全部 12 组及代码/计划附加组。关键页面在相同数据、时间、主题和视口下比较截图；动态计时或字体渲染差异单独核对，结构和交互断言必须保留。

回退：每个功能模块一批，撤回后恢复原入口对应职责；磁盘结构保持一致，防止回退丢失新写入的记录。

### P5：主进程服务与启动组装

P5a：存储/设置/本地数据、计划、比赛数据源与缓存。

P5b：平台采集、平台服务、GitHub、标签、算法目录服务。

P5c：认证、离线格式化、外部链接、按功能拆分 IPC 注册，最后缩减 main 入口。

要求：

- 保留凭据加密和安全存储、用户目录位置、原文件名、原子写入方式、历史数据归一化与未知字段。
- 保留 sender 检查、资料库范围、所有权、管理员权限和服务端新鲜状态校验。
- 原 write/sync/update/platform 锁及锁释放路径必须共用，不能拆成互相独立的“局部锁”后失去原互斥。
- 保留网络超时/重试/分页上限、缓存行为、统计口径和未知结果提示。
- 格式化引擎保持动态加载、离线执行和失败不丢代码。

验收：相关服务和 main 全量单测、真实 Electron preload/IPC、隔离 profile 的保存与重启；涉及远端写入的场景在专用测试资料库验收，不向正式资料库写测试记录。

回退：按服务或 IPC 功能组撤回，维持数据格式和频道兼容；认证与更新锁相关改动整组撤回。

### P6：更新、独立 helper 与发布工具

P6a：差分 codec、manifest、下载状态、存储清理、备份恢复。

P6b：update-helper、file-upgrade、启动恢复与安装互斥。

P6c：签名/差分 feed、打包/安装器、CI 发布及更新通道激活工具。

必须满足：

- helper 为可复制到任意事务目录独立执行的单个 CJS 文件，无相对运行时 import、编译运行库或额外 chunks。
- preload 仍满足 sandbox/contextIsolation；renderer 无 Node 能力。
- Electron RunAsNode、等待父进程退出、校验/备份/替换/重启/恢复顺序不变；保留 macOS 手动更新限制。
- 签名前完成编译和归档；五平台使用同一签名归档；prebuiltAsar 在打包完整性元数据计算前注入。
- 从可信 checkout 编译发布工具；签名私钥仅在原授权步骤可见；扩展可信源码比较范围到 TS、配置、构建输入和实际依赖链。
- 发布保持草稿 → 成品验收 → 公开发布 → 更新通道合并的顺序。

验收：全部更新/发布单测、复制 helper 的 Node 与 Electron RunAsNode 执行、篡改/超时/断流/回滚；先无发布的构建演练，再按真实五平台流程生成候选包。检查跨平台路径/大小写/资源，并确认归档 SHA 一致。

回退：源码改动可撤回；已激活更新通道的恢复必须按合法签名和版本策略操作，不能强行把旧版本标成新版，也不能未经方案覆盖用户安装目录。

### P7：完整回归、候选验收和清理

任务：

- 在干净 Windows/Linux/macOS 构建环境执行类型、单元、数据与打包检查。
- 跑全部现有 UI 组及附加组，检查测试导入和实际发布产物属于同一版本。
- 用旧版 v1.2.4 创建的隔离数据副本验收本地题解、草稿、收藏、复习、计划、设置、知识节点/笔记、学习进度，重启后仍一致。
- 在候选包验证 v1.2.4 → 重构版本差分/全量、原位置安装、失败恢复，检查用户数据哈希和应保留字段。
- 在测试账户/资料库验收登录、取消、同步、上传、编辑、删除、权限不足和网络失败。不要把模拟结果记成真实账号验收。
- 完成 Windows x64、Linux x64/arm64、macOS x64/arm64 构建；当前主机无法实际运行的架构明确记录，不能把构建成功写成桌面实机通过。
- 移除已迁移旧 JS、兼容全局与临时适配；排查重复初始化、悬挂监听和计时器；保留仍有实际用途的 CJS 测试及最小引导文件。

最终门槛：下节完成定义全部满足。发布版本号、标签、线上 Release 和稳定通道的实际操作另按发布任务执行；本计划本身不发布。

## 5. 每批检查与留档模板

每批开始：写明基线提交、迁移职责、旧入口、新入口、保留行为、所用旧数据和相关检查。

每批完成：

```text
批次：P?x
提交：<SHA>
范围：<模块及调用方>
类型覆盖：<本批新增、仍未迁移>
行为差异：无 / 单独列明且不归入纯重构
验证：类型 / 相关单元 / 相关UI / 桌面或包
结果：通过数、失败、跳过与原因
兼容：存储、IPC、节点ID、生成数据、升级
限制：未实测平台或真实账号场景
回退：需整体撤回的提交及数据影响
```

开发时先跑本批相关检查，批次收尾跑 `pnpm check:refactor`；修改共享状态、公共阅读、导航或跨进程层时跑全量界面回归。整阶段或候选发布前再做完整回归。新增测试针对尚未覆盖的兼容边界和真实风险，不写只复述实现的测试。

## 6. 最终完成定义

- 手写业务模块已迁移 TS；生成数据、静态资源、测试及必要引导按用途保留合适格式，不以所有文件改后缀为目标。
- 所有迁移模块严格检查，无新增 ts-nocheck/ts-ignore 或以 any 掩盖接口；第三方类型不足时只在小边界适配。
- runtime 不需要 ts-node/tsx/编译器，不扩大 renderer/preload 权限。
- 入口按职责组装，无重复运行实现；业务改动可以定位到对应 feature/service。
- 开发、测试、打包引用同一构建布局；干净锁文件安装与跨平台构建可复现。
- 基线功能、旧数据、IPC、权限、并发锁和更新恢复验收通过；跳过项和未实测范围明确。
- 迁移说明更新到实际目录、命令、类型覆盖和剩余工作；清理临时产物。

## 7. 工作量与首批执行建议

以下是评估区间，不是交付承诺；按单人串行开发、包含检查与问题修复估算，真实账号/其他设备验收等待另计。

| 阶段 | 估算工作日 | 风险 |
| --- | --- | --- |
