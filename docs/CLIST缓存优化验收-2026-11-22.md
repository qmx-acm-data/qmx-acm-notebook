# CLIST 缓存优化验收（2026-11-22）

## 最终行为

- 正常首次启动自动合并随应用分发的 37,200 条 CLIST 正分基线，不需要 Key；保留个人较新评分与独有题目。初始内容哈希相同且本机缓存有效时不重复写入。
- 设置优先显示分页批量缓存：每次请求最多 1,000 条，按六个资源站点依次请求，遵守共享请求队列的六秒间隔。页后合并并保存游标，支持暂停和重启续传。
- 单题强制刷新、共享文件导出／导入、公开 HTTPS 来源同步继续保留，人工／AI 补充与原生难度优先级保持原逻辑。
- 共享面板分别显示评分记录数与本地题库实际匹配数，避免把跨站记录数当成本地覆盖数。
- AtCoder 缺少精确链接时，只按完整且区分大小写的相同 task ID 复用缓存；同 task 存在不同评分则拒绝回退。精确链接始终优先，存储键不改写。
- 主进程按评分文件版本复用已校验 reader；评分文件变化后重新读取，避免每次抽题重复解析整份基线。

## 基线来源

源为 2026-11-22 实际完成的 CLIST API v4 分页导出：42 次请求，37,726 条正分记录；当前客户端支持链接规则的共享包为 37,200 条。526 条不支持的路径未加入客户端基线，完整外部导出仍保留原始记录。

基线 SHA-256：`2fafaf15946ca25360242eed932d12bd2b522cb0adf34518f38c03507abe2dad`。

数据只含官方题目链接、CLIST rating、资源站点和查询时间，不含 Key、用户名、个人备注或解题状态。静态元数据随应用记录来源、数量、哈希与已知限制。

## 实际验证

- 完整本地题库：60,918 题、383,655 次 draw／评分／等级／标签／排除检查通过，无远端查询，分片未改写。这是本地逻辑复验，不代表逐题在线 CLIST 查询。
- 真实 Electron 默认 sandbox/contextIsolation：正常无 Key 首次启动、初始合并、个人较新评分保留、重启零重复写、非法 sender 拒绝通过。
- 分页桌面测试使用合成 CLIST 页面：先 1,000 条后 1 条，暂停后重启仅请求 offset 1,000 的下一页，空资源完成，六秒限流通过。此项不冒充真实在线分页请求。
- 双用户共享缓存、匿名 HTTPS 同步模拟、正常同步自动合并、错误保留、零分过滤、原生难度优先及无凭据导出通过。
- 真实 60,918 题索引与 37,200 条缓存的 main IPC 抽题共 35 次，无 CLIST 查询。各平台中位耗时约 18～77 ms，全平台约 275 ms；这只是当前 Windows 验收环境测量。
- 16 个与评分缓存无关的现有配置、个人补充及题库文件哈希保持不变。验收缓存由 704 条有效正分合并为 37,200 条，未覆盖更晚个人数据。
- 34 组 UI 回归通过；严格类型、生成一致性、语法与单元检查通过，最终 843 项中 842 项通过、1 项跳过。
